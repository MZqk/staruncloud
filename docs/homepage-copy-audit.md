## 一句话结论

**需要调整，但不用重写。** 版式和气质是这份首页最值钱的部分，别动。
问题集中在三处，按收益排序：

1. **首屏信息顺序是倒的** —— 唯一说清「能帮我干什么」的那句话排在最后、字号最小。
2. **六张卡片用同一个句式写了一遍** —— 读完记不住任何一张的区别。
3. **5 个链接是 404** —— 文案承诺「打开后期工作台」，点下去是「找不到此页面」。

第 3 条不是文案问题，但不修，前两条改了也白改。

## 一、先处理三个非文案问题

### 1.1 六个项目，五个链接 404（实测）

| 卡片 | 链接 | HTTP 实测 |
| --- | --- | --- |
| Starun 网页版 | `/web` | **404** |
| Starun 桌面端 | `/pc` | **404** |
| Starun 手机端 | `/mobile` | **404** |
| DeepSky Skills | `/deepsky-skills` | **404** |
| 望远镜对照表 | `/telescope` | 301 → `/telescope/` ✅ |
| 暗空地图 | `/map` | **404** |

主 CTA「开始一次后期」同样指向 `/web` → **404**。

线上真正活着的是 `/`（上传页）、`/analysis`（专业分析）、`/processing`（AI 自动出图）、`/compare`、`/history`。

**结论**：在 `dist/` 上线之前，要么补齐这 5 个路由，要么先把卡片改成「建设中」状态，要么直接把 href 换成活着的路径。三条路选一条，不能维持现状。

### 1.2 根域首页被 noindex

```
https://starun.cloud/  →  <meta name="robots" content="noindex">
```

`/analysis`、`/telescope/` 没有这个标签，只有根域首页和 404 页有。

如果是内测期有意为之，忽略这条。**如果打算靠搜索获客，这件事的优先级高于本文所有文案建议** —— 在 noindex 状态下，标题、描述、H 标签的优化全部无效。

另外：`/robots.txt` 和 `/sitemap.xml` 均不存在（请求返回的是站点 404 页面）。

### 1.3 首页和根站的定位撞车

| | title |
| --- | --- |
| 根站 | `Starun \| 深空后期智能处理平台` |
| 本首页 | `Starun · MZZZ 的星空工具箱` |

同一个域名，两个「Starun」：一个自称平台，一个自称个人工具箱。访客分不清这是产品官网还是个人博客。

**先定角色，再定文案。** 本文按「品牌门户」写方案（介绍 MZZZ 的整套工具，把人分流到各产品）；如果它其实是 Starun 后期平台的官网，那六张卡片应该收缩成「平台 + 望远镜对比」两条主线，而不是并列六个。

## 二、首屏：把最重要的一句话从最后一行提到第二行

访客在 5 秒内实际读到的顺序：

| 顺序 | 当前文案 | 信息量 |
| --- | --- | --- |
| 1 | `MZZZ'S PERSONAL OBSERVATORY` | 0，纯装饰 |
| 2 | **把热爱，写进星空。** | 0，好看 |
| 3 | 你好，我是 MZZZ，一名开发者。 | 0，访客不关心 |
| 4 | 我把对星空的好奇，做成触手可及的工具。 | 0.5，抽象 |
| 5 | 从选择器材、寻找暗空，到完成下一张深空作品。 | **1.0，唯一说清楚的一句** |

最好的信息被放在最后，字号最小；最没用的自我介绍占了第一句的位置 —— 而 `#about` 段已经写过「我是 MZZZ。Starun 是我的个人项目集合」，首屏重复了一遍。

### 改写方案

**Before**

```
MZZZ'S PERSONAL OBSERVATORY
把热爱，写进星空。
你好，我是 MZZZ，一名开发者。
我把对星空的好奇，做成触手可及的工具。
从选择器材、寻找暗空，到完成下一张深空作品。
[探索我的项目]  [开始一次后期 ↗]
```

**After**

```
DEEP SKY TOOLKIT · BY MZZZ
把热爱，写进星空。
从挑一台智能望远镜、找一片够暗的天空，到把一张 FITS/XISF 处理成能发出去的作品——
这条路上要用的工具，我一件件做了出来。
MZZZ，一个人维护的星空工具箱。
[看看有哪些工具 →]  [直接处理一张图 ↗]
```

改动说明：

- **H1 不动。** 它是品牌资产，也是整个版式的视觉主角，换掉可惜。缺的信息由下面三行补。
- 第 1 行翻到第 2 行，第 3 行删掉（`#about` 已有）。
- 英文小标从「PERSONAL OBSERVATORY」（自说自话）换成「DEEP SKY TOOLKIT」（说品类）。
- **次 CTA 换目标**：「开始一次后期」→ `/web` 是死的；改成「直接处理一张图」→ `/analysis`（活的），承诺具体、可达。
- 主 CTA「探索我的项目」→「看看有哪些工具」：主语从「我的」换成访客视角。

## 三、六张卡片：同一个句式写了六遍

量化一下现状：六条描述全部是「情绪句 + 功能句」两段式，情绪句 7–12 字，功能句 14–20 字。

```
在浏览器里，发现深空影像的更多可能。 FITS / XISF 图像分析、AI 后期辅助与效果对比。
把完整的后期流程，留在你的电脑。     基于 Siril 的自动处理，支持离线运行。
让深空后期，随你一起出发。           在手机上打开 FITS / XISF，离线处理与分享。
给你的 AI 助手，一套深空摄影技能。    从拍摄顾问、图像诊断，到叠加与马赛克拼接。
下一台望远镜，从看懂差别开始。        并排比较关键参数，找到适合自己的观星伙伴。
星空拍摄污染图，给下一次出发一个方向。在地图中了解光污染分布，寻找星光更清晰的地方。
```

节奏完全一致，读六张和读一张没有区别。**唯一的解法是让功能句带具体到无法复制的名词和数字。**

还有一层结构问题：六张卡里混了三种东西 ——

- 同一个产品的三个端（网页 / 桌面 / 手机）
- 一个独立产品（DeepSky Skills）
- 两个工具页（望远镜对比、暗空地图）

访客建立不了「这是 1 个产品还是 6 个产品」的模型。建议给网格加两个分组标签（**后期工具** / **拍摄决策**），或者把三个端合并成一张卡 + 三个入口。

### 逐卡改写

| # | 现名 | 改写后描述 | 改动理由 |
| --- | --- | --- | --- |
| 1 | Starun **网页版** | 上传线性 FITS/XISF，先拿到星点、噪声与动态范围的诊断报告，再选一套风格自动出图。 | 「更多可能」→ 具体三步流程；对齐真实功能 `/analysis` `​/processing` |
| 2 | Starun **桌面端** | 整条后期流水线跑在本机，基于 Siril 自动叠加与拉伸，原片不出硬盘。 | 「留在你的电脑」太文艺；「原片不出硬盘」是深空用户真正的顾虑 |
| 3 | Starun **手机端** | 在 Android 上直接打开 FITS/XISF，通勤路上也能修完一张。 | 「随你一起出发」→ 给出具体场景 |
| 4 | DeepSky **Skills** | 一套 Agent Skill：拍前算曝光与构图，拍后诊断星点，再交给 Siril 完成叠加与马赛克拼接。 | 把「拍摄顾问 / 图像诊断 / 叠加」翻译成动作序列 |
| 5 | **望远镜对照表** | Seestar、DWARF 全系并排对比：口径、传感器、单张曝光上限、内后期能力，价格一起看。 | 缺的正是「智能望远镜」这个真实搜索词，和两个真实品牌名 |
| 6 | 找一片更暗的天空 | 按波特尔等级看附近的光污染，找到最近一个能拍出银河的点位。 | 「污染图」是生造词，行业叫「光污染地图」；补「波特尔」「银河」两个搜索词 |

**卡片标题也要动两处：**

- 「Starun 网页版 / 桌面端 / 手机端」→「Starun **在线后期** / 桌面版 / 安卓版」。「网页版」是渠道描述，不是能力描述。
- 「望远镜**对照表**」→「**智能**望远镜对照表」。加两个字，直接对上搜索意图。

**排序也要动**：望远镜对照表是六张里唯一活着的、也是唯一带购买链接（商业意图最强）的页面，现在排第五、在网格左下角。应该提到第二位 —— 首位给 Starun 在线后期（主线产品），次位给望远镜对比（唯一能转化的流量入口）。

## 四、SEO 元数据：四个必填项全缺

```html
<!-- 现状 -->
<title>Starun · MZZZ 的星空工具箱</title>
<meta name="description" content="MZZZ 的个人星空工具箱。探索 Starun 网页、macOS 与 Android 天文后期工具、望远镜对照表、深空摄影 Skills 和星空拍摄污染图。">
```

问题：

- title 20 字，只有品牌词，没有品类词。「星空工具箱」不是任何人会搜的词。
- description 78 字，`探索` 是 explore 的直译，中文不这么说话；罗列六个品类但没一句利益点；结尾没有动作。
- `canonical` / `og:url` / `og:image` / `twitter:card` / `application/ld+json` —— **全部缺失**（grep 命中 0）。分享到微信或 Twitter 时没有卡片图，对个人 IP 站是很明显的损失。

### 替换建议

```html
<title>Starun 星空工具箱｜FITS 后期与智能望远镜对比</title>
<meta name="description" content="在浏览器里读取线性 FITS/XISF，拿到星点、噪声与动态范围诊断，再生成一版成片；另有 7 款智能望远镜横向对比和暗空地图。MZZZ 独立开发。">
<link rel="canonical" href="https://starun.cloud/">
<meta property="og:url" content="https://starun.cloud/">
<meta property="og:image" content="https://starun.cloud/og-cover.jpg">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta name="twitter:card" content="summary_large_image">
```

`og:image` 需要单独做一张 1200×630 —— 现有的 `assets/nebula.jpg` 是 1600×1067（3:2），在 1.91:1 的卡片里会被裁掉约 20% 的上下边缘。

结构化数据建议加 `WebSite` + `Person` + `ItemList`（六个项目），把 MZZZ 和六个产品绑成一个实体图，这是个人开发者站最容易吃到的一口权威度：

```json
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "name": "Starun",
  "url": "https://starun.cloud/",
  "author": { "@type": "Person", "name": "MZZZ", "sameAs": ["<填真实链接>"] }
}
```

（`sameAs` 填 GitHub / 微博 / 小红书的真实主页地址，别填不确定的。）

## 五、不建议改的部分

| 内容 | 理由 |
| --- | --- |
| H1「把热爱，写进星空。」 | 品牌资产，视觉主角，换掉要重排版式 |
| 「微弱的光，也值得被看见。」 | 全站最好的一句，放在星云图上位置也对 |
| 英文全大写小标（保留，但别再加） | 现在是 9 处标语 + 6 个平台标签，已经是上限。装饰性英文在中文页里是噪音，多了就是「翻译腔设计」 |
| 「一个开发者，一些关于星空的想法。」 | `#about` 的定位准确，E-E-A-T 意义上比任何产品参数都值钱 |
| 暗空地图放最后 | 低频需求，位置合理 |
| 三条 `FOLLOW YOUR CURIOSITY` 路径 | 结构清晰，但它和上面六张卡片功能重复 —— 要么删掉这节，要么把它当成唯一的导流入口、六张卡片只做展示 |

### 最后一条值得单独说

`#projects`（六张卡）和 `#workflow`（三条路径）在做同一件事：把人分流到产品。
现在页面里连着两个导流区，第二个还叫「今晚，想从哪里开始？」—— 访客刚看完六个入口，又被问一次从哪开始。

建议：**保留 `#projects` 做展示（按用途筛选是它的价值），把 `#workflow` 删掉**，或者反过来 —— `#workflow` 做导流、`#projects` 缩成三行文字清单。两个都留，等于没有主次。
